# Do Tabular Foundation Models Pay Off for Churn?

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23696051.svg)](https://doi.org/10.5281/zenodo.23696051)

Code, per-split predictions and paper source for **"Do Tabular Foundation Models Pay Off for Churn? A Profit-,
Calibration- and Tuning-Aware Re-evaluation"** (Ismail Hossain Polas, Jahangirnagar University). The paper PDF is
[`paper/main.pdf`](paper/main.pdf); arXiv link to follow.

We compare four tabular foundation models (TabPFN-2.5, TabPFN-3.5, TabPFN-3.5-Fast, TabICL v2) against Optuna-tuned
LightGBM, XGBoost and CatBoost, plus EBM and logistic regression. The comparison covers five public telecom churn
datasets, with ten seeded 60/20/20 splits each. Every model is scored on ranking metrics, on expected maximum profit
(EMP), on e-Profits, on a fixed-threshold campaign policy, on calibration and on scoring time, with a split-aware corrected
t-test, Holm correction over the pre-declared primary family, and two-level bootstrap intervals.

## Reproduce

Three levels, from cheapest to complete.

**1. Every table and number in the paper, from the released results (seconds, no installs).**
```bash
python3 paper/audit.py          # regenerates paper/tables/ and runs the consistency checks
cd paper && tectonic main.tex   # or latexmk -pdf main.tex; needs the LNCS class (llncs) and splncs04
```
`audit.py` uses only the Python standard library. It regenerates every table and in-text number from
`results/kernels/analysis/` and fails if anything differs from the committed files. It also checks that all runs
succeeded and that all models used identical, disjoint splits.

**2. The analysis, from the released predictions (minutes, CPU).**
Open [`notebooks/02_analysis.ipynb`](notebooks/02_analysis.ipynb). On Kaggle, attach the prediction notebooks as inputs.
Locally, point `CHURN_INPUT` at a folder of prediction outputs. Recomputing metrics needs the labels, which we do not
redistribute (see *Data* below). Run step 3 with the datasets attached and it writes them as `data_side.npz`.

**3. Everything, from the raw data (GPU, about 10–15 T4-hours in total).**
Open [`notebooks/01_predict.ipynb`](notebooks/01_predict.ipynb) on Kaggle. Set `DATASET` and `GROUP`, then attach the
dataset listed in the notebook. Foundation models need a T4 GPU and a TabPFN licence token, stored as the Kaggle Secret
`TABPFN_TOKEN`. To run the whole grid the way the paper did:
```bash
cd kaggle/bench
./make_kernels.sh push telco maven cell2cell iranian orange ecommerce   # CPU + GPU kernels per dataset
SEEDS="5,6,7,8,9" ./make_kernels.sh push telco maven cell2cell iranian orange   # seeds 5-9 (10 seeds in total)
./make_kernels.sh push orange-context cell2cell-context timing          # ablation and scoring-time kernels
./make_kernels.sh push orange-strong cell2cell-strong iranian-strong    # 200-trial LightGBM and CatBoost (CPU)
./make_kernels.sh push telco_dupgroup iranian_dupgroup ecommerce_dupgroup  # duplicates kept, split by group
./run_queue.sh                       # waits for every kernel the analysis reads, then runs the analysis kernel
```
The kernel IDs in `kaggle/bench/` belong to the author's Kaggle account; change the `ipolas/` prefix to your own.

## Layout

| Path | Contents |
|---|---|
| `kaggle/bench/predict.py` | Prediction stage: data loading and de-duplication, splits, tuned GBDTs, foundation models, context ablation, scoring-time benchmark |
| `kaggle/bench/analyze.py` | Analysis stage: AUC, PR-AUC, lift, EMP, e-Profits, campaign policy, calibration, bootstrap CIs, rank agreement |
| `kaggle/bench/make_kernels.sh`, `run_queue.sh`, `analysis-kernel/` | Kaggle kernel definitions and the job queue used for the paper |
| `notebooks/` | The same code as notebooks for review, generated by `tools/make_notebooks.py` |
| `results/kernels/<kernel>/` | Released kernel outputs: `runs.json` (status and timing), `preds/*.npz` (calibration and test probabilities with split indices, per model and seed), `data_meta.json`, logs |
| `results/kernels/analysis/` | Analysis outputs that every paper table is generated from |
| `paper/` | Manuscript (`main.tex`), bibliography, `make_tables.py`, `audit.py` and generated `tables/` |
| `kaggle/gate_test/` | The early feasibility test that motivated the study (not used in the paper) |

The scripts are the source of truth. After editing one, rebuild the notebooks with `python3 tools/make_notebooks.py`.

## Data

All six datasets are public, and none is redistributed here. The code fetches them from their original sources:
Kaggle (Telco, Maven, Cell2Cell, Iranian mirror, E-Commerce), OpenML (Orange KDD Cup 2009, data id 1112) and UCI
(Iranian, DOI 10.24432/C5JW3Z). Several carry non-commercial or attribution-only licences, so `results/` holds model
outputs and split indices but no labels or feature values.

## Model licences

TabICL v2 weights are BSD-3. The TabPFN-2.5 and TabPFN-3.5 weights have custom licences that allow research and
evaluation but not production use; see the paper, Sect. 4.6. Running step 3 requires accepting the TabPFN licence.
